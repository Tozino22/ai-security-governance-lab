OWASP LLM05

Improper Output Handling — Live Range

A review-summariser that runs a model, then puts the result on the page. The model does its job correctly every time. Whether the page is safe is decided entirely by how the app places that output — the one thing you control with the switch below.

Brief

Your shop has a feature: "summarise the reviews for this product." It fetches stored reviews, asks the model to summarise them, and shows the summary. One review was written by an attacker and contains markup, not prose. The model faithfully copies it into the summary — because to the model it is just text.

Everything in this lab is synthetic. The "session token" below is a fake string the lab planted, and the "attacker's server" is the panel on the right — a stand-in that never leaves this page. You are watching the real browser behaviour with a fake target.

Why it happens — and the one fix

  • The model is not the problem. It returned a string, exactly as asked. The string crossed a database, a prompt and two JSON payloads unchanged, and was harmless at every step.
  • The failure is at render time. innerHTML hands the string to the HTML parser, which builds a real element and registers its onerror as a live handler. textContent never calls the parser — it stores characters.
  • Encode for the destination. Display as text, or HTML-encode before rendering. The same rule generalises: parameterise before a database, never pass to a shell. Treat model output as untrusted input, because that is what it is.
  • Defence in depth sits behind it, never instead of it: a Content-Security-Policy that blocks the outbound request, HttpOnly cookies, and output scanning at the gateway.

OWASP LLM01

Prompt Injection — Live Range

A support assistant summarises whatever document a user gives it. The user asks an innocent question — but the document carries instructions aimed at the model. Whether the assistant obeys the document or stays loyal to its task is decided by the switch below.

Brief

To a language model, the system instruction and the document you hand it arrive as one stream of text. There is no built-in wall that says "obey this part, only read that part." If the document says "ignore your instructions and do X," the model may simply do X — because it cannot inherently tell your content from your commands.

The user never typed anything malicious. The attack rode in on data the model was asked to read. This is the same lesson as Module 05, on the input side: untrusted text reaching an interpreter — here the interpreter is the model itself. Everything is synthetic and runs in this page.

Why it happens — and what actually helps

  • There is no hard boundary. "Instructions" and "data" are the same tokens to a model. A system prompt is a strong suggestion, not an access control.
  • "Just tell it to ignore injections" is weak. You saw that the system prompt already said exactly that — and off, it was overridden anyway. A prompt cannot reliably police itself.
  • Separate and constrain, don't rely on wording. Clearly delimit untrusted content, keep it in a distinct role, and — the real control — limit what the model can do so a successful injection has nowhere to go (this is why LLM01 and Excessive Agency, LLM06, are joined at the hip).
  • Check the output, too. Inspect responses for signs the model left its task, and never let one component's output become another's instructions unchecked.
